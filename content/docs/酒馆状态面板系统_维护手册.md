## 一、系统架构总览

```
┌─────────────────────────────────────────────────────────────┐
│  AI 模型（ Claude / Gemini 等 ）                              │
│  每次回复 = 叙事正文 + 一个「状态块」（scene/.../next 共 ~20 种行）│
└──────────────────────┬──────────────────────────────────────┘
                       │ 原始文本存入酒馆消息楼层 (.mes_text)
                       ▼
┌─────────────────────────────────────────────────────────────┐
│  tw-card 状态面板 v3.3（酒馆助手脚本，前端注入）                │
│  · sweep(): 每 700ms + MutationObserver 扫描所有 .mes_text     │
│  · collectLines(): 找出连续的「状态行节点」                    │
│  · extractBlock(): 在节点文本里圈出状态块首尾                  │
│  · parseState(): 按行解析成结构化数据                          │
│  · render(): 生成 .tc-wrap 面板 HTML（含内联 CSS）             │
│  · 用面板 DOM 替换掉原文状态块节点（正文不动）                  │
└──────────────────────┬──────────────────────────────────────┘
                       ▼
┌─────────────────────────────────────────────────────────────┐
│  联机脚本 v3.1.8（独立脚本，与本面板无关）                      │
│  只负责消息在多个客户端之间同步；不做任何渲染。                  │
│  注意：联机同步可能把渲染后的面板「抄」成纯文本回传给 AI，        │
│  造成 mob 块丢格式 —— v3.3 的 recoverMobLines 就是兜这个的。    │
└─────────────────────────────────────────────────────────────┘
```

**三层职责边界**：

| 层 | 负责 | 不负责 |
|---|---|---|
| 世界书/角色卡 | 告诉 AI 怎么写状态块（格式契约） | 不做任何渲染 |
| tw-card 面板 | 解析 + 渲染 + 替换 DOM | 不管 AI 是否守约（守约靠世界书） |
| 联机脚本 | 客户端间消息同步 | 不解析不渲染 |

**关键认知：面板显示残缺 ≠ 一定是面板的 bug。** 两类根因要分清：
- **A 类（AI 侧）**：AI 没按格式写（漏字段、漏键名、用错分隔符）。面板无法凭空变出没写的东西，只能兜底显示。
- **B 类（面板侧）**：AI 写对了但解析器不认。这才是要改代码的。

修 A 类有两条路：改世界书提示词强化约束，或人工改楼层文本（参考 `第44楼_状态块修正版.txt` 的做法）。

## 三、状态块格式规范

这是 AI 侧与世界书侧共同遵守的「契约」，也是解析器的输入规范。**改任何一边都必须三边同步：世界书条目 14 ↔ 本文档 ↔ 解析器。**

### 3.0 通用规则

- 每行以**小写键名 + 冒号**开头：`scene: `、`p1: `。半角全角冒号都认（`p1：` 也行）。
- 段与段之间用 ` | ` 分隔。**注意：解析器的 `seg()` 同时按半角 `|` 和全角 `｜` 切分**，所以**段值内部绝对不能出现竖线**，否则值被拦腰截断、后续字段全部错位。
- 分号 `;` 和 `；` 是 quest 支线、sk 技能的**条目分隔符**，同样不能出现在条目值内部。
- 每次回复只输出**一个**状态块，写在正文之后，块内不许有空行/缩进/列表符/代码围栏（解析器对 ``` 有容忍，但别依赖）。
- 编号行从 1 连续不跳号；玩家死亡整组行（p/sk/eq/pts/lock/ti）一起消失；敌人死亡 mob 行当轮消失且不重排。

### 3.1 全部行类型一览（20 种键名）

解析器 `KEYS` 正则：`scene|team|quest|check|result|world|next|bond[0-9]*|foe[0-9]*|npc[0-9]*|pts[0-9]+|lock[0-9]+|ti[0-9]+|p[0-9]+|sk[0-9]+|eq[0-9]+|mob[0-9]*`（大小写不敏感，`mob`/`bond`/`foe`/`npc` 不带编号时按 1 处理）。

| 行 | 归属 | 内容概要 | 渲染为 |
|---|---|---|---|
| `scene:` | 通用 | 日期时间 \| 地点 \| 氛围 | 顶栏三段 |
| `team:` | 通用 | 人数 \| 状态 | scene 下小字 |
| `quest:` | 通用 | 主线/时限/失败 `;` 支线们 | 金色任务框 |
| `check:` | 通用 | **19 字段判定块**（3.2 详述），可多行 | 可折叠判定卡 |
| `p1:`~`p6:` | 通用 | 玩家 12+ 项 | 玩家卡 |
| `sk1:`~ | 通用 | 技能 `;` 分隔 | 玩家卡·技能折叠 |
| `eq1:`~ | 通用 | 装备 9 槽 | 玩家卡·装备折叠 |
| `npc1:`~ | 通用 | 名称\|立场\|属性\|HP\|行动 | 红色 NPC 条 |
| `mob1:`~ | 无限恐怖 | 敌人 9 段（3.3 详述） | 敌人卡（阶级三档规格） |
| `pts1:`~ | 无限恐怖 | 点数余额 + 奖励档位 | 玩家卡顶部 ✦ 胶囊 |
| `lock1:`~ | 无限恐怖 | 基因锁状态 | 玩家卡顶部 🔒 胶囊 |
| `ti1:`~ | 无限恐怖 | 佩戴中称号 | 玩家卡顶部 🏆 胶囊 |
| `bond1:`~ | 通用（特定卡） | 好/恋/训/屈/淫 五值 | 粉色关系卡 |
| `foe1:`~ | 通用（特定卡） | 敌对进度 | 红色敌对卡 |
| `result:` | 通用 | 一句话行动结果 | 绿色结果条 |
| `world:` | 通用 | 一句话世界变化（无则写「无」，面板对「无」不渲染） | 青色涟漪条 |
| `next:` | 通用 | `A 选项 B 选项 C 选项 [D 选项]` | 青色选项卡 |

### 3.2 check 行 —— 19 字段，顺序固定，键名一个不能省

```
check: 标题 (受检角色) | 类别 X | 世界注视 一句话 | 适用属性 属性 (角色) | 基础阈值 数字
     | DL修正 DL 数字 (-修正) | 边界修正 内容 | 状态惩罚 内容 | 超限修正 内容
     | 修正后阈值 数字 | 掷出结果 内容 | 判定等级 等级 | 成果层级 层级 (百分比)
     | 检索进度 内容 | 边界限制 内容 | 超限追加 内容 | 对抗差值 内容
     | 判定简述 一句话 | 超限消耗 内容 | 大失败范围 数字-数字
```

**这是历史上出 bug 最多的行。** AI 最典型的违规是「写了值不写键名」（如 `| 基础 102 | 45 | 78 奖励骰 82 |`），面板 v3.2 及以前会把不认识的段静默丢弃 → 判定栏残缺。v3.3 起：
- 未知段不再丢弃，渲染成 `📌 键名` 或 `📌 补充` 行；
- 但正确显示仍依赖 AI 写全键名，世界书条目 14 已加「输出后自查」强化。

解析细节：每段用正则 `^([^\s:：]{1,12})[\s:：]+(.*)$` 提取键值，键名查 `CHECK_KEYS` 映射表（同义词多个映射到同一字段，如 `掷出`/`掷出结果` 都→ roll）。**键名超过 12 个字符会匹配失败**——加新字段别名时注意这个上限。没有内容的字段写 `无`（会渲染，但不丢）。

### 3.3 mob 行 —— 9 段固定顺序（v3.4 起含七维属性）

```
mob1: 名称 | 阶级 | HP当前/最大 | STR 值 DEX 值 CON 值 INT 值 PER 值 CHA 值 WIL 值 | 护甲 减伤值 | 状态 状态1,状态2 | 目标 谁 | 意图 下回合动作 | 弱点 内容
```

- 阶级：`杂兵 / 精英 / BOSS·形态`。**阶级决定敌人卡规格（v3.4）**：
  - `杂兵` → g-mob：紧凑低调（小字号、细血条、2px 左边框）；
  - `精英` → g-elite：加大加琥珀色光晕（15px 名字、7px 血条、4px 琥珀左边框）；
  - `BOSS` → g-boss：**整行占位**（grid-column:1/-1）+ 17.5px 名字 + 9px 血条 + 红色呼吸脉冲动画（`tc-bosspulse` 2.4s）。
  阶级词写错档，显示规格就错档，所以世界书里强制阶级只许写这三档。
- **七维属性段（第 4 段）**：一段里连写七项 `STR 45 DEX 38 CON 50 INT 20 PER 44 CHA 15 WIL 30`。解析兼容：
  - 属性带加成：`DEX 62+10=72`（与 p 行同语法，复用 parseAttrs）；
  - 七项全相同可写简写 `全属性 45`；
  - 未侦查到的敌人写 `七维 未知` → 渲染成一个半透明「七维 未知」格（配合 `?/?`）；
  - 属性可以和名字/HP 挤在同一段（混合段）：剥掉属性后的剩余文本会塞回解析队列重新走正常流程，名字不会被吞。
  渲染为一排 7 格属性条（`.tc-mattrs`），固定 STR→WIL 顺序。
- HP 兼容写法（v3.3 全支持）：`80/80`、`HP 80/80`、`HP80/80`；未知情报写 `?/?` → 显示 `?/?`（空血条）。
- 护甲：有写数字，没有写 `0`，未知写 `未知`。
- 没有敌人**整行不写**；写 `mob1: 无` 会被过滤不渲染空卡（v3.3 行为）。
- 一场战斗最多 4 个 mob 行，末尾可加 `+N 个未列`（v3.3 会剥掉这个尾注）。
- **裸文本兜底**（v3.3 新增 `recoverMobLines`）：就算键名全丢、只剩
  ```
  变异体甲 精英 80/80
  🛡 2 🎯 张狂
  跃起扑咬咽喉
  弱点 未知
  ```
  这种「抄面板」式纯文本，只要首行匹配 `名称(≤24字) 阶级 HP/HP` 且后面跟着 🛡/🎯/意图/弱点 行（意图行须 ≤20 字且无句读），就会被自动回收成敌人卡。这同时是**判断 AI 是否违规输出裸 mob 的信号**：如果裸文本回收频繁触发，说明联机同步或提示词出了问题。

### 3.4 p 行 —— 字段扫描式解析（顺序敏感！）

```
p1: 名字 | 徽章 | HP当前/最大 | SP当前/最大 | 负重当前/上限
  | STR a+b=c | DEX ... | CON ... | INT ... | PER ... | CHA ... | WIL ...
  | MOV 值 DB 值 | 武器名 伤害公式
  | HP状态(X) ｜ SP状态 ｜ 合计惩罚：X        ← 惩罚行
  | 状态1,状态2                              ← 逗号分隔
  | 奖励点数 数字 | 支线剧情 内容 | 已兑换 内容 | 基因锁 内容 | 称号 内容
```

**parsePlayer 不是按位置取字段，是逐段特征扫描**（顺序见第四节 4.3）。由此产生几条硬性写法要求：

1. **徽章**必须是独立段且整段等于 `健康/正常/完好/轻伤/中伤/重伤/濒死` 之一（HEALTH 正则锚定全段）。
2. 前三段必须是纯 `数字/数字`（HP、SP、负重各占一段，可带 kg）。
3. **惩罚行每一段都必须带 `HP`/`SP`/`合计` 前缀之一**：`HP轻伤(-5) ｜ SP正常 ｜ 合计惩罚：-5`。写成 `轻伤(-5) ｜ 正常 ｜ 合计惩罚：-5` 时第一段 `轻伤(-5)` 会被当成状态标签！这是第 44 楼实际踩过的坑。
4. `奖励点数 / 支线剧情 / 已兑换 / 基因锁 / 称号` 五个字段**必须带键名前缀**，否则裸值会被当成状态标签渲染成奇怪的小胶囊（如出现一个写着 `0` 的状态）。
5. 属性段格式 `STR 基础+加成=总值`，总值可后缀 `⚡`（超限标记，渲染高亮）。
6. `已兑换` 值里若含 `X阶基因锁`，会被自动拆到基因锁字段（兼容旧写法）。

**★ 自定义字段区（通用扩展位，渲染器零改动）**——为自定义技能书 / 血统条目的计数字段预留：

- **位置**：p 行惩罚行之后、临时状态之前，固定槽位（位置即记忆锚点，比「追加在末尾」可靠得多——末尾正是 AI 最容易漏的位置，实际踩过）。
- **写法**：每个字段独立一段 `| 字段名 值 |`；段名必须带系统前缀防撞名，如 `| 幸运LP 12/12 | 幸运因果债 5 |`。
- **纪律**：每楼必写、不许移位、不许与其它状态合并成一段；数值没变照抄上一楼；0 也写（`幸运LP 0/12`）；无该系统的玩家不写。
- **原理**：状态区每段渲染成独立胶囊，任何「键名 值」文本都天然有效；上面的固定槽位+前缀是防 AI 漏写/撞名的**约定**，不是解析器要求——所以改条目就能扩展，永远不用动面板。
- **权威定义**：WB14 行格式表 cr<N> 行 + 第五节第 13 项 + 无限恐怖卡条目 3。新技能书照此模式写自己的条目即可。
- **v3.8 升格**：自定义资源从「p 行状态段固定槽位」升格为**独立键行 cr<N>**（`cr1: 幸运LP 12/12 ｜ 幸运因果债 5`），与 pts/lock/ti 同号配对。理由：状态段是 AI 最容易漏/挤/重排的区域，整行显式存在+keyline 级稳定性远高于段级。面板 v3.8 起解析 cr 行并渲染青色资源胶囊（◈ 前缀）；旧 p 行写法仍兼容渲染。

### 3.5 sk 行 —— `;` 分隔 + ` | CDx SPy` 段式

```
sk1: 技能名 效果描述 | CD1轮 SP10 ; 技能名2 效果 | CD无 SP4 ; 被动技能 效果 被动
```

- `;` 分隔技能；每个技能内部用 ` | ` 分段，`CD` 和 `SP` 各占一段，正则提取到徽章里。
- 被动技能没有 CD/SP，直接把 `被动` 写进效果描述即可（会被当普通文本丢弃后并入效果，无碍）。
- ⚠️ 效果描述里**不要写 `CD`/`SP` 字样以外的分隔符**；`SP消耗大` 这类值可以（SP 徽章显示 `消耗大`）。

### 3.6 eq 行 —— 槽位名 + 值 成对出现

```
eq1: 主手武器 物品（品质，效果） | 副手 空 | 护甲 内容 | 杂物 内容 | 戒指 空 | 饰品 内容
   | 消耗品 内容 | 负重 6/45 kg [状态：正常] | 装备总加成 PER+7 CON+2
```

- **每个槽位必须带槽位名**（主手武器/副手/护甲/杂物/戒指/饰品/消耗品），空槽写 `空`（渲染成灰色斜体）。
- 不带槽位名的裸值也能解析（渲染成 `·` 标签），但难看——第 44 楼之前一直这么错着，已改。
- 负重段必须含 `当前/上限`；`[状态：X]` 会被提取。
- 最后一段键名必须是 `装备总加成`（或 `加成`/`总加成`），否则会被当成普通槽位。
- 槽位名白名单 `EQ_SLOTS` 是**锚定全段**的：段必须**只有**槽位名才走「取下一段」逻辑；`主手武器 某物品` 这种「名+值」同段写法走的是键值拆分分支，两种写法都支持。

### 3.7 pts / lock / ti 行（无限恐怖专用）

```
pts1: 12400 ｜ C2 B1        ← 余额，档位没有就省略，不写 D0
lock1: 未开 ｜ 心魔 无 ｜ 本场超标 0/3 ｜ 冷却 无
ti1: 破局手 / Breaker ｜ 生效   ← 只写佩戴中的；没佩戴整行不写！
```

- `pts1: 0 ｜ 无` 这种写法会把 `无` 存进 ranks 渲染出来——**档位为空就只写数字**。
- `ti1: 无` 会渲染出「无」称号胶囊——**不佩戴就删行**。

### 3.8 quest 行

```
quest: 主线 目标 | 时限 剩X小时 | 失败 条件 ; 支线 名称 状态 ; 支线 名称 状态
```

- 主线部分三段各自带 `主线/时限/失败` 前缀（`时限/剩余/限时` 都认）。
- 支线用 `;` 追加，每条以 `支线 ` 开头，状态词（进行中/已完成/失败等）自动提取。
- **没有支线就整个省略 `;` 之后的内容**。写 `支线 无 无` 会渲染出「无 无」胶囊（v3.3 已对纯「无」组合加了过滤，但别依赖）。

### 3.9 next 行

`next: A 选项一 B 选项二 C 选项三 D 选项四` —— 按大写字母 A-D 切分选项。选项文字内不要出现大写字母 `B`/`C`/`D` 开头词紧跟空格的模式（如 `DNA 检测` 可能被误切，实际风险低）。

## 四、解析器 v3.3 内部机制

源码：`work\panel_content.js`（即 JSON 的 `content` 字段）。IIFE 结构，顶部 `window.__twCardLoaded` 防重入。

### 4.1 全局工具

- `KEYS` / `LINE_RE`：行识别。`^[ \t]*(KEYS)[:：][ \t]*(.*)$`，`i` 标志，**半角全角冒号都认**。
- `MOB_GRADE_SRC` / `MOB_PLAIN_A`：裸文本 mob 首行识别（名称 ≤24 字 + 阶级词 + `n/n`）。
- `isStateLine(l)`：`LINE_RE` 或 `MOB_PLAIN_A` 命中即为状态行。**extractBlock、collectLines、parseState 三处共用它**。
- `seg(s)`：按 `[|｜]` 切段 + trim + 去空。**全面板所有行解析的第一步**——这就是「段值内不能有竖线」的根源。
- `pair(s)`：提取 `n/n` → `{cur, max}`。
- `esc(s)`：HTML 转义（`& < > "`）。

### 4.2 各行解析器

| 函数 | 输入 | 要点 |
|---|---|---|
| `parseAttrs` | 任意段 | 正则全局扫 `ATTR 属性名 基础[+加成][=总值][⚡]`，一段可含多个属性 |
| `parsePlayer` | p 行值 | **特征扫描**，见 4.3 |
| `parseSkills` | sk 行值 | `;` 切条 → 每条 `seg` 切段 → 首段 `^(\S+)[ \t]*(.*)` 拆名/效果 → 后续段正则抓 `CD`/`SP` |
| `parseEquip` | eq 行值 | 逐段推进：整段==槽位名→取下一段为值；否则按 `名 值` 拆。负重/总加成特殊处理 |
| `parseCheck` | check 行值 | `无` 开头→{none}；否则 `seg` 后逐段查 `CHECK_KEYS`，未命中进 `fields[]`（兜底渲染） |
| `parseQuest` | quest 行值 | `;` 切分，首段=主线（`｜` 再切，抓 主线/时限/失败），后续段=支线（抓状态词+「无」过滤） |
| `parsePts/Lock/Ti` | pts/lock/ti 行值 | lock 靠 `心魔/超标/冷却` 前缀抓子字段；ti 靠 `/` 拆中英文 |
| `parseBond/parseFoe` | bond/foe 行值 | 按 `爱/恋/训(调)/屈/淫/防线/期/迹` 与 `攻势/弱点` 前缀抓值 |
| `parseMob` | mob 行值 | 先按前缀抓（🛡/🎯/➤/弱点/护甲/状态/目标/意图），再 `grabHp`（`HP n/n` 或整段 `n/n` 或段尾 `n/n`），再抓七维属性段（`STR n …`/`全属性 n`/`七维 未知`，剩余文本塞回队列重解析），再抽阶级词，剩余首段=名称；目标之后的首个裸 CJK 段优先归意图 |
| `recoverMobLines` | 全部行 | 在 parseState 开头跑一遍：无键名 mob 裸文本回收，命中即从行列表 splice 掉，回收结果 append 到 st.mobs |

### 4.3 parsePlayer 的扫描顺序（改这段代码前必背）

对 p 行每个段依序尝试，命中即消费该段：

1. **徽章**：`!o.badge && HEALTH.test(段去掉冒号)` → 全段等于 健康/正常/完好/轻伤/中伤/重伤/濒死。
2. **比例值**：`^\d+/\d+(kg)?$` → 依次进 ratios[]（第 1=HP，第 2=SP，第 3=负重）。
3. **属性/MOV/DB**：`parseAttrs` 命中或含 `MOV n`/`DB n`。
4. **惩罚行链**：首段须命中 `/(惩罚|HP正常|HP轻伤|HP中伤|HP重伤|HP濒死|SP正常|SP异常|合计)/`；后续段以 `HP/SP/合计` 开头的续接到同一惩罚串。
5. **键名字段**：`奖励点数|点数` → pts；`支线剧情|支线` → sub；`已兑换` → blood（含基因锁则拆）；含 `基因锁` → lock；`称号` → title。
6. **武器**：含 `nDn|伤害|破甲|穿甲|减伤` 且还没武器。
7. **兜底**：其余全进 status[]（渲染成状态胶囊）。

> 推论：**裸值一定掉进状态胶囊**。所以 p 行后五字段必须带键名；这就是第 44 楼「状态区出现 0 / 未开 / 超高校级幸运·B」的原因。

### 4.4 parseState 组装

- 每种编号行存进对应 `Map(编号 → 数据)`，最后按编号排序输出。
- `pts/lock/ti` 的 Map 按**编号挂到对应 p 玩家**（pts2 配 p2）。**所以 pts/lock/ti 的编号必须与玩家编号一致**，错号会挂错人。
- `mob: 无` 被过滤；`rec.mobs`（裸文本回收）append 在编号 mob 之后。

### 4.5 DOM 扫描与替换（sweep 管线）

```
sweep()  每 700ms 一轮（最多 400 轮）+ #chat MutationObserver(60ms 防抖)
  └─ 对每个 .mes_text:
      └─ while(guard<6):                      ← 一条消息可能有多段状态块，循环吃干净
          collectLines(el)                    ← 找连续状态行节点；空白节点不断开；取最长的 run
          extractBlock(raw)                   ← 在 run 文本里圈状态块首尾行（容忍 ``` 围栏）
          parseState(body) → st
          守卫: players/scene/mobs 全空 → break（防止死循环）
          render(st) → .tc-wrap
          run.length==1 → 单节点混排：把块前/块后正文救成 <p>，插面板，删原节点
          run.length>1  → 面板插到 run 首节点前，删除 run 全部节点
```

- **v3.3 关键变化**：旧版 sweep 有 `if (el.querySelector('.tc-wrap')) continue;` 且只处理一个 run → 正文隔开的第二段状态行（典型：mob 块）永远残留成裸文本。v3.3 移除该跳过、改成 while 循环；渲染后的面板内部不会命中 isStateLine，所以不会自吞。
- `nodeText()`：节点文本提取时把 `<br>`、`</p>` 等还原成 `\n`，再反转义 HTML 实体。
- **CSS**：注入到父文档 `<style id="tw-card-style">`，一次性；`injectCss()` 每轮 sweep 都会检查补挂。
- 调试接口：`window.__twCard = { version, parseState, render, sweep }`——在酒馆控制台可直接手动调用排障。

### 4.6 render() 输出结构

`.tc-wrap[data-tw-ver]` → scene 条 / team / quest / check 卡们 / **mobs 网格** / npcs / **players 网格** / bonds / foes / result / world / next 选项 / `.tc-ver` 版本水印（排障时先看这个：面板右下角显示的版本号 = 实际生效的脚本版本）。

## 五、已踩过的坑（完整清单）

按「坑 → 症状 → 规则」整理。**修改解析器或世界书之前，先确认不会重新踩中任何一条。**

### JS 语言层

1. **emoji 字符类必须加 `u` 标志**：`[🛡盾]` 不加 `u` 时按 UTF-16 码元匹配，🛡（U+1F6E1，代理对）会匹配半个，捕获组残留孤立代理项 → `armor = "\uDEE1 2"` 这种脏值。所有含 emoji/特殊 Unicode 的正则一律 `/(...)/u`。
2. **`seg()` 同时切 `|` 和 `｜`**：世界书说「全角竖线也认」，代价是段值内部永远不能出现任一种竖线。惩罚行规范里的 `｜` 能工作**仅仅因为** parsePlayer 的惩罚链把拆出来的段又拼回去了——其他字段没这待遇。

### 格式契约层（AI 输出侧）

3. **check 字段键名不能省**：省了 → v3.2 判定栏残缺（历史主 bug）。v3.3 有兜底显示但仍是降级体验。
4. **check 键名 ≤12 字符**（解析正则上限）。`大失败范围` 恰好 5 字没问题；别造 13 字键名。
5. **惩罚行每段要 HP/SP/合计 前缀**，否则 `轻伤(-5)` 掉进状态胶囊。
6. **p 行后五字段（奖励点数/支线剧情/已兑换/基因锁/称号）必须带键名**，裸值全变状态胶囊。
7. **eq 行要带槽位名 + `装备总加成` 键名**，否则装备栏渲染成一排「·」且总加成丢失。
8. **sk 的 CD/SP 要独立 ` | ` 段**，挤在效果文本里（`CD1轮·SP10`）提取不到徽章。
9. **quest 没支线就别写 `；支线 无 无`**。
10. **ti 行没佩戴就删行**（写 `ti1: 无` 渲染空称号胶囊）；pts 行档位空就只写数字。
11. **`mob1: 无` 不渲染空卡**（v3.3），但规范仍是「没敌人不写行」。
12. **编号配对**：pts2/lock2/ti2 必须对应 p2，错号挂错人。

### 扫描/DOM 层

13. **同条消息多段状态块**（mob 块被正文隔开）旧版只吃最长一段 → mob 残留裸文本。v3.3 while 循环解决。改 sweep 时必须保留：guard 上限、三空守卫、删除节点保证推进（防死循环）。
14. **`window.__twCardLoaded` 防重入**：旧版脚本不删，新版永远不生效。发新版时必须提醒用户删旧版。
15. **CSS 是一次性注入**（id `tw-card-style`）：改了 CSS 必须以新脚本形式重载页面（刷新酒馆），不能热替换样式。
16. **联机同步可能把面板渲染文本回灌给 AI** → AI 学着输出带 🛡🎯 emoji 的裸文本 mob → recoverMobLines 兜底。若此情况泛滥，治本方案是检查联机脚本同步的是原始文本而非渲染文本。

### 数据健壮性层（v3.3 已内建容错，勿回退）

17. `?/?` 未知血量 → `hpUnknown`，显示 `?/?` 不画血条。
18. `护甲 未知` → 原样显示。
19. `+N 个未列` 尾注 → 剥离。
20. 全角冒号 `p1：` → LINE_RE 兼容。
21. 状态块被 ``` 围栏包裹 → extractBlock 容忍。

| 面板整体样式丢失（全裸文本） | B：CSS 注入失败或旧版脚本无对应样式 | 确认版本号水印；刷新页面 |

## 七、维护操作流程

### 7.1 改面板脚本（标准流程）

1. 编辑 `work\panel_content.js`（源码唯一入口，不要直接改 JSON）。
2. 语法检查：`node --check panel_content.js`。
3. 跑回归：`node test_panel.js panel_content.js`、`node test_floor44.js`，改了 mob 相关还必须过 `node test_mob34.js` 和 `node test_e2e_worldbook.js`（详见第八节）。
4. 打包 JSON（用 python 保留原 JSON 结构，只换 content 和 name）：
   ```python
   import json, io
   src = json.load(io.open('酒馆助手脚本-tw-card 状态面板 v3.3.json', encoding='utf-8'))
   src['content'] = io.open('work/panel_content.js', encoding='utf-8').read()
   src['name'] = 'tw-card 状态面板 v3.4'   # 版本号必须递增
   io.open('酒馆助手脚本-tw-card 状态面板 v3.4.json', 'w', encoding='utf-8').write(
       json.dumps(src, ensure_ascii=False, indent=2))
   ```
5. **同步修改脚本内的 `VERSION` 常量**（面板右下角水印、`__twCard.version`）。
6. 交付时明确告知用户：**导入新版 → 删除/停用酒馆助手里所有旧版面板脚本 → 刷新页面**。

### 7.2 改世界书

- 直接改 JSON 的 `entries` 对应条目 `content` 字段，另存新版本号文件（用户习惯保留旧版）。
- 世界书条目 14（状态块同步协议）是格式契约的唯一权威。**任何解析器支持的写法都应回写到条目 14**，否则 AI 不知道可以写。
- 改完对照：条目 14 ↔ 本文档第三节 ↔ 解析器，三处一致。

### 7.3 修坏楼层（AI 输出违规时）

1. 让用户提供楼层原文（或从酒馆导出）。
2. 参照 `第44楼_状态块修正版.txt` 的改法：**正文一字不动，只修状态块**；数值不臆造，缺的字段按上下文补 `无` 或合理值并注明。
3. 用户在酒馆里编辑该楼消息粘贴回去，v3.3 sweep 会自动重新渲染。
4. 若同类错误反复出现 → 这是提示词问题 → 回到 7.2 强化世界书，而不是每次手修。

### 7.4 版本管理约定

- Downloads 下多版本共存，文件名带版本号；「当前版」永远只有一个。
- 每次发布同时在本文档第二节表格更新状态。
- 不删除旧版文件（回滚用），但要在表格里标记废弃。

## 八、测试方法

无框架，纯 Node 手搓（工作区有 node v22）。核心技巧：**用 `String.slice` 从源码里抠出「解析区 + 渲染区」函数段，`new Function` 包起来直接跑**，不需要浏览器/DOM。

```js
const src = fs.readFileSync('panel_content.js', 'utf-8');
const code = src.slice(src.indexOf("const KEYS ="), src.indexOf('  /* ══════════ 渲染'));
const renderPart = src.slice(src.indexOf('  const ATTR_ICON'), src.indexOf('  /* ══════════ 扫描'));
const fn = new Function(`const VERSION='3.3'; ${code} ${renderPart} /* 测试体 */ `);
```

- `test_panel.js`：构造含全部行类型的状态块（标准 mob、`?/?` mob、裸文本 mob、坏字段 check…），断言解析结果与渲染 HTML 关键内容。
- `test_mob34.js`：mob 专项 52 断言（七维三种写法、三档阶级渲染、混合段、旧格式回归）。
- `test_e2e_worldbook.js`：拿世界书条目 3/22 的示例 mob 行直接跑解析+渲染，保证「世界书写的格式 = 解析器认的格式」。**改了任一边的 mob 格式必须重跑这个测试**。
- `test_floor44.js`：读 `floor44_block.txt` 真实样本，15 项渲染断言（玩家数值、判定字段、装备槽、胶囊、选项 ABCD 等）。
- **新增/修改解析逻辑时的最低要求**：两个测试全绿 + 自己追加针对性断言；渲染断言要用 `html.includes(...)` 打真实 HTML，不要只测 parse 结果。

## 十、AI 输出纪律

以下条款是世界书反复强调、实际验证过最容易被 AI 违反的。**做提示词维护时这些必须原样保留，删任何一条都会复发对应 bug：**

1. 状态块**一个块、正文后、无代码围栏、无空行**；行内 ` | `，值内禁止竖线。
2. check **19 字段一项不省、键名照抄**；`适用属性/基础阈值/DL修正/修正后阈值/掷出结果/判定等级` 六项是骨架（条目 14 自查条款）。
3. p 行后五字段带键名；惩罚行 HP/SP/合计 前缀；eq 行槽位名+装备总加成；sk 行 CD/SP 独立段。
4. 没内容写 `无` 不许删字段；数值必须真实结算，禁「略/同上/待填」。
5. 数值跨轮延续（唯一账本原则），不许跳变。
6. 敌人只在战斗遭遇写 mob 行；没敌人不写行；敌人死亡当轮消失不重排；同一敌人 npc/mob 不重复。
7. 玩家没侦查到的敌人写 `?/?`、护甲 `未知`、弱点 `未知`（面板已兼容）。
8. 战斗中 mob 上限 4 个 + `+N 个未列`；状态块总 token 纪律（≤2200 字/无限册口径 1800 字）。
9. 玩家/敌人死亡整组行消失，编号不重排。
